# skillsrc

**Manage your `.agents/skills`.**

`skillsrc` installs, updates, and removes skills in a project's `.agents/skills`. Sources can be Git repositories or
local directories. Add `-g` to manage `~/.agents/skills` instead.

In a project, `skills.toml` lists selected skills. `skills.lock` pins Git commits and records content hashes. Commit
both files instead of the installed skills. Run `skillsrc sync` in another checkout to recreate them.

`skillsrc` refuses to overwrite an existing skill unless the active manifest owns it.

## Install

`skillsrc` needs Git at runtime. Building from source also needs Go 1.24 or later:

```sh
go install github.com/jordi9/skillsrc/cmd/skillsrc@latest
```

To install from a checkout:

```sh
make install
```

## Quick start

### Project skills

Run these commands in the directory where you want `skills.toml`:

```sh
cd path/to/project
skillsrc init
skillsrc add owner/repository@skill-name
```

`add` writes the selected skill to `skills.toml`, updates `skills.lock`, and installs it under `.agents/skills`.

Run `discover` first if you do not know the skill name. It does not need `skills.toml` and does not change configuration
or installed skills:

```sh
skillsrc discover owner/repository
skillsrc add owner/repository@skill-name
```

Commit `skills.toml`, `skills.lock`, and the root `.gitignore`. Other checkouts need one command:

```sh
skillsrc sync
```

`sync` installs Git skills at their locked commits and refreshes skills from local sources.

### User skills

Use `-g` from any directory to manage `~/.agents/skills`:

```sh
skillsrc -g init
skillsrc -g add owner/repository@skill-name
```

You can also work directly from `~/.agents`. There, `skillsrc` selects user scope automatically, so you can omit `-g`.

```sh
cd ~/.agents
skillsrc init
skillsrc add owner/repository@skill-name
```

## Project files

`skillsrc init` creates `skills.toml`, updates the root `.gitignore`, and writes `.agents/.gitignore`. The first
successful `add` or `sync` also creates `skills.lock` and installs the selected skills:

```text
project/
├── skills.toml
├── skills.lock          # created by the first add or sync
├── .gitignore
└── .agents/
    ├── .gitignore       # generated by skillsrc
    └── skills/          # managed skill directories
```

The root `.gitignore` ignores the generated `.agents/.gitignore`. That generated file ignores each managed skill by
name. Git still shows every unmanaged skill under `.agents/skills`, including skills you created there yourself.

## skills.toml

Each source sets either `repo` or `path` and names one or more skills.

```toml
version = 1

[[sources]]
repo = "owner/repository" # also accepts HTTPS and SSH Git URLs
ref = "main"              # optional branch, tag, or full 40-character commit hash
skills = ["one", "two"]

[[sources]]
path = "../local-skills"  # relative, absolute, and ~/... paths
skills = ["private-skill"]
```

### Override model invocation

To disable automatic model invocation for a skill, prefix its name with `!` or use the explicit form:

```toml
skills = [
    "ordinary-skill",
    "!manual-only",
    { name = "another-manual-skill", disable-model-invocation = true },
]
```

A name prefixed with `!` tells `skillsrc` to add `disable-model-invocation: true` to the installed `SKILL.md`. The
explicit TOML form does the same thing. Neither form changes the source files or their lock hash. You cannot list both
`"one"` and `"!one"` because they name the same skill.

### Discovery

`skillsrc` must discover every selected skill in its source. Two sources cannot select the same skill name.

`skillsrc` looks for skills in:

- the source root when it contains `SKILL.md`
- immediate child directories
- `skills/*` and one category level below it in grouped repositories
- `.agents/skills/*`
- `.claude/skills/*`
- local paths listed in `.claude-plugin/marketplace.json` or `.claude-plugin/plugin.json`, including conventional
  `skills/*` directories
- local paths listed in `.cursor-plugin/marketplace.json` or `.cursor-plugin/plugin.json`

Skill paths from plugin manifests must stay within the repository. `skillsrc` ignores remote URLs, absolute paths, and
paths that escape the repository. `skillsrc` reads Claude and Cursor metadata to find skills, then validates and hashes
them like other discovered skills.

If a skill name appears in more than one discovery location, the higher-priority location wins. `skillsrc` treats
identical marketplace copies as one skill. For conflicting marketplace copies, it keeps the first declaration. `add` and
`discover` print the chosen and ignored paths. `skillsrc` rejects other same-priority conflicts as ambiguous.

`skillsrc` copies a relative file symlink as a regular file when its target stays inside the selected skill. It rejects
a symlink if it is absolute, escapes the skill, points to a directory, is broken, or forms a cycle.

## Commands

```sh
skillsrc init                                      # create skills.toml in the current directory
skillsrc discover SOURCE                          # list discovered skills without changing configuration
skillsrc discover SOURCE --ref REF                # inspect a branch, tag, or full commit hash
skillsrc add SOURCE                               # install its sole skill, or list choices when there are multiple
skillsrc add SOURCE SKILL...                      # declare selected skills, update the lock, and install them
skillsrc add OWNER/REPO@SKILL                     # add one skill with the OWNER/REPO@SKILL shorthand
skillsrc add SOURCE SKILL... --invoke-user-only   # add skills with automatic model invocation disabled
skillsrc add SOURCE --all                         # declare and install every skill discovered in the source
skillsrc add SOURCE --all --invoke-user-only      # add every discovered skill with model invocation disabled
skillsrc add SOURCE SKILL... --ref REF            # add from a branch, tag, or full 40-character commit hash
skillsrc remove SKILL...                          # remove declarations and their owned installations, then sync
skillsrc sync                                     # install declared skills from locked Git commits or local sources
skillsrc outdated [SOURCE|SKILL...]               # report changed remote skills or local sources without modifying files
skillsrc update [SOURCE|SKILL...]                 # advance matching Git sources, update the lock, and sync installations
skillsrc list [--all] [--json]                    # show configured state, optionally including unmanaged skills or JSON
skillsrc doctor [--repair] [--json]               # diagnose managed state, optionally repair it or emit JSON
skillsrc version                                  # print the installed skillsrc version
```

Run `skillsrc <command> --help` for complete arguments and options.

### Initialize a manifest

Project `init` writes `skills.toml` to the current directory. It does not search for the Git root. It rejects nested
configurations and refuses to initialize directly in `$HOME`. It will not overwrite an existing manifest. `skillsrc -g
init` initializes `~/.agents` without project Git ignore files. `add` requires a manifest, so run `init` first.

### Discover skills

`discover` lists skills in a Git repository or local directory. You can run it before `init`; it does not change the
manifest, lockfile, or installed skills. For Git sources, `--ref` selects a branch, tag, or full commit hash.

```sh
skillsrc discover owner/repository
skillsrc discover ../local-skills
skillsrc discover owner/repository --ref v1.2.0
```

### Add and remove skills

A source can be GitHub shorthand, an HTTPS or SSH Git URL, or a relative, absolute, or `~` local path:

```sh
skillsrc add owner/repository              # install its sole skill, or list multiple choices
skillsrc add owner/repository one two      # add named skills
skillsrc add owner/repository@one          # add one skill using shorthand
skillsrc add owner/repository --all        # add every discovered skill
skillsrc add ../local-skills private-skill # add from a local directory
```

Use `--ref` with a Git source to select a branch, tag, or full commit hash. `--invoke-user-only` adds `!` to each
selected skill name and disables automatic model invocation in the installed copy. Use it with explicit skill names or
`--all`. You cannot combine `--all` with explicit skill names.

Without skill names, `add` installs a skill only when the source contains one unique name. With zero or multiple names,
it lists the available skills without changing the manifest. `add` validates selections before changing the manifest. It
installs newly selected skills but does not refresh or repair existing ones. For an already locked Git source, `add`
uses the locked commit. If that commit lacks the requested skill, run `skillsrc update <source>` and retry.

`remove` deletes the named declarations and any source blocks left empty. It removes an installed skill only when the
selected manifest owns it. It does not update the remaining Git sources. `rm` is an alias for `remove`.

### Check, synchronize, and update

These commands have different effects:

| Command | Changes locks? | Changes installations? | Purpose |
| --- | --- | --- | --- |
| `outdated` | No | No | Check remote skill updates and unsynchronized local changes |
| `sync` | Missing entries and local hashes | Yes | Reproduce the declared and locked skill set |
| `update` | Yes, for selected Git sources | Yes | Advance Git revisions and then synchronize |

`sync` makes installed skills match the manifest. Git sources stay at their locked commits. For local sources, `sync`
rereads the files and updates their lock hashes. It also creates missing lock entries and removes managed skills that
are no longer declared.

`outdated` fetches configured Git refs and compares each selected skill's content hash with its locked hash. A Git
source is up to date when its selected skills are unchanged, even if other repository files changed. Updates list the
changed skill names and short commit hashes. Each update also shows an exact tag when available, or the commit date
otherwise. `outdated` does not change project files or installed skills. For local sources, it reports whether content
matches the lock.

`update` resolves selected Git refs again and then runs `sync`. With no selectors, it updates every Git source.
Selectors can be repositories, local paths, or skill names. `outdated` accepts the same selectors. Local sources have no
remote revision, but `update` still syncs their current content. Full commit refs do not move.

See [docs/lockfile.md](docs/lockfile.md) for the generated lock format.

### Inspect and repair

```sh
skillsrc list           # show configured skills and installation state
skillsrc list --all     # also show valid standalone unmanaged skills
skillsrc doctor         # report lock, install, cache, and project metadata problems
skillsrc doctor --repair # restore repairable managed state
```

`skillsrc` does not take ownership of standalone skills shown by `list --all`. If an unmanaged skill has the same name
as a declared skill, the configured skill gets the `collision` state. `list` prints one row for that name. `ls` is an
alias for `list`.

`doctor --repair` runs `sync`, then reports anything still broken. You must resolve unmanaged collisions yourself.

By default, `skillsrc` caches Git repositories in `<OS user cache>/skillsrc/repos`. On macOS, that is
`~/Library/Caches/skillsrc/repos`. Use `--cache` to choose another directory. Concurrency lock files also live in the
user cache, not the project.

## Scope selection

Commands search upward from the current directory for the nearest `skills.toml`. If none exists, they do not fall back
to user configuration. `~/.agents` is the exception. Commands run there select user scope and print a short notice.

```sh
skillsrc sync     # nearest project skills.toml
skillsrc -g sync  # ~/.agents/skills.toml
```

Project commands never change files in `~/.agents`.

## Safety and recovery

Each managed skill contains a `.skillsrc-managed.json` marker tied to its manifest. `skillsrc` replaces or removes the
directory only when that marker names the active manifest as its owner. An existing file, symlink, unmarked directory,
or directory owned by another manifest causes a collision. `skillsrc` stops without changing that target. `skills.lock`
records source and upstream content hashes.

To replace a skill, `skillsrc` stages the new copy and writes a transaction journal. It moves the current copy to a
backup before publishing the replacement. If a command stops during a replacement or removal, the next command that
writes files runs recovery first. `skillsrc doctor` checks locks, installed skills, the cache, and project Git ignore
files. `skillsrc doctor --repair` fixes installations and project files when it can. Move or remove unmanaged collisions
yourself.

Locks and hashes reproduce files. They cannot tell whether a skill's instructions are safe. Review sources and lockfile
changes before installing or updating. See [SECURITY.md](SECURITY.md) for vulnerability reporting and the exact trust
boundaries.

## Releasing

Tags trigger releases. The release script requires an empty jj working-copy change directly after local `main`. Local
`main` must match `origin/main`:

```sh
./release.sh --dry-run
./release.sh
```

The release script uses git-cliff to prepend the next version to `CHANGELOG.md`. It then opens the file with `$VISUAL`,
`$EDITOR`, or `vi`. Edit the generated section before confirming. The script commits and pushes the changelog, tags that
commit, and CI publishes the edited section as GitHub release notes.
